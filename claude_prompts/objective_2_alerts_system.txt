> does it make sense to also store the streak / the number of consecutive out of stock updates? or the the date for the last "in

⏺ Good questions!

  Storing the streak count / last in-stock date:
  I'd recommend not storing these directly on the alert. Here's why:

  1. Streak count: If we store it, we'd need to update the alert record every time a new out-of-stock InventoryChange comes in.
  This creates extra write operations and the potential for the count to get out of sync. Instead, we can calculate it on-the-fly
  by counting consecutive out-of-stock InventoryChanges for that product/store combo - it's a simple query and always accurate.
  2. Last in-stock date: Same reasoning - we can derive this by finding the most recent InventoryChange where inventory_present =
  true for that product/store. Storing it would mean updating it if we ever backfill data or if there's a correction.

  The downside of deriving is slightly more database queries on the show page, but for a read-only display that's usually fine. If
  performance becomes an issue later, we could add caching or denormalize then.

  Naming:
  Yes, InventoryAlert is better - more specific and leaves room for other alert types in the future (e.g., PriceAlert). I'll use
  that name.
