Objective 3 - Performance

Paginated Views

> in our views we have many places where we render inventory changes the lists are quite large and we need to implement pagination
in order to improve performance of our system. please implement a dead simple, reusable, handrolled pagination system to help us
improve performance by limiting the number of records we show to the user at a given time. the pagination limit should be 20 but
let's make that defined in a single place so that its easy to change. the user should see simple pagination controls like
"previous" and "next" links and the total count. we will need something that can be reused across views for example product, brand,
 and store views all need paginated lists for inventory changes. since this is a ruby on rails app we should use some of the
application structure to help us organize this code. please add a model concern for query reusability in
app/models/concerns/paginatable.rb this can be mixed in to each model as needed. in our controllers we can refer to the pagination
methods on the given models. we should also use a view helper we can define in app/helpers/pagination_helper.rb which can define a
#pagination_links method that is reusable across views. make sure the pagination query logic uses limit and offset. our dataset is
not large enough to warrant cursor-based pagination.
